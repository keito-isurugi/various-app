**現状の問題**: Read Uncommitted（ダーティリード許容）が抜けている。

**追加すべき内容**:
4つの分離レベルを全て挙げるべき:
1. Read Uncommitted: 他のトランザクションのコミットされていない変更も読み取れる（ダーティリード発生）
2. Read Committed: コミット済みのデータのみ読み取れる（現状の記述通り）
3. Repeatable Read: 同一トランザクション内で同じクエリは同じ結果を返す（現状の記述通り）
4. Serializable: 完全な直列化（現状の記述通り）

各分離レベルで発生しうる異常（ダーティリード、ファジーリード、ファントムリード）の表を追加すると効果的。

## 4. 技術的に不正確・改善が必要な箇所

### 4.1 JS Q6: プリミティブ型とオブジェクト型

**問題箇所**: 「オブジェクトは参照渡し」

**修正内容**: 厳密にはJavaScriptは「参照の値渡し（call by sharing / call by object reference）」。関数内で引数に別のオブジェクトを再代入しても呼び出し元には影響しない。これが真の参照渡し（C++の`&`等）との違い。面接で指摘される可能性があるため、以下のように修正を推奨:

> 「オブジェクトは参照の値が渡されるため（call by sharing）、関数内でプロパティを変更すると元のオブジェクトに反映されますが、引数自体に新しいオブジェクトを再代入しても元の変数には影響しません。」

### 4.2 React Q2: 仮想DOM

**問題箇所**: 「React Fiberと呼ばれるインクリメンタルなレンダリングを可能にする新たな差分検出処理アルゴリズム」

**修正内容**: Fiberは正確には「差分検出処理アルゴリズム」ではなく「再レンダリングエンジンのアーキテクチャの再設計」。Fiberアーキテクチャの本質はレンダリング作業を小さなチャンクに分割して中断・再開可能にすることで、React 18のConcurrent Featuresの基盤となっている点にも触れるべき。

### 4.3 Programming Language Q1: GCの説明

**問題箇所**: 「永続領域」という表現

**修正内容**: JVM 8以降では「永続領域（PermGen）」は廃止され「メタスペース（Metaspace）」に置き換えられた。面接で「最近のJVMでは？」と聞かれた場合に対応できるよう、この点に触れるべき。

### 4.4 OS Q6: 仮想メモリ

**問題箇所**: 「ディスクストレージ上の一部分」という説明が不完全

**修正内容**: 仮想メモリの本質は「各プロセスに独立した仮想アドレス空間を提供する仕組み」であり、ディスクへのスワップはその一機能にすぎない。現状の説明だと「スワップ = 仮想メモリ」という誤解を与える可能性がある。

### 4.5 JS Q24: CommonJSとES Modules

**問題箇所**: ES Modulesを「非同期的」と表現している

**修正内容**: ES Modulesは**静的に解析可能**（import/exportがトップレベルでコンパイル時に確定する）であり、これがTree Shakingを可能にする理由。CommonJSのrequire()は動的（実行時に解決）。非同期かどうかよりも、静的解析可能性が本質的な違い。

### 4.6 JS Coding Q5: Promiseチェーンの出力

**問題箇所**: 回答に解説がほとんどない

**追加すべき内容**: 各ステップの処理を説明すべき:
1. `Promise.resolve(1)` → resolved(1)
2. `.then(value => console.log(value * 2))` → `2`を出力、returnがないのでresolved(undefined)
3. `.then(() => { throw new Error(...) })` → rejected
4. `.catch(error => 3)` → エラーをキャッチし、resolved(3)を返す
5. `.finally(() => console.log(4))` → `4`を出力（finallyは値を変更しない）
6. `.then(console.log)` → `3`を出力
7. `console.log(7)` → 同期処理なので最初に実行

### 4.7 Web Security Q2: CORS

**追加すべき内容**: プリフライトリクエスト（OPTIONS）の仕組みに触れるべき。面接で「CORSの流れを具体的に説明してください」と聞かれた場合、Simple RequestとPreflight Requestの区別を説明できることが重要。
- Simple Request: GET/HEAD/POSTで特定のContent-Typeの場合、プリフライトなし
- Preflight Request: それ以外の場合、OPTIONSメソッドで事前確認

## 5. 不足している重要トピック

### 5.1 Backend側で不足しているトピック

#### 認証・認可（最重要）

メガベンチャーでは認証は必ず聞かれるトピック。

**追加すべき質問**:

> **Q: OAuth 2.0の認可フローについて説明してください**
>
> OAuth 2.0は、サードパーティアプリケーションがユーザーの認証情報を直接扱わずにリソースへのアクセスを委任するための認可フレームワーク。主要なフローとして以下がある。
> - Authorization Code Flow: Webアプリ向け。認可コードをトークンと交換する最もセキュアなフロー
> - Authorization Code Flow with PKCE: SPAやモバイルアプリ向け。コードベリファイアで認可コードを保護
> - Client Credentials Flow: サーバー間通信（M2M）向け。ユーザーの介在なし
> - OpenID Connect: OAuth 2.0の上に認証レイヤーを追加した規格。IDトークン（JWT）でユーザーの身元を確認

> **Q: セッションベース認証とトークンベース認証の違いを説明してください**
>
> セッションベース: サーバー側にセッション情報を保持し、CookieでセッションIDをやり取り。ステートフル。
> トークンベース: JWTなどのトークンをクライアントが保持し、リクエスト毎に送信。ステートレス。スケールしやすいがトークン失効管理が課題。

#### CI/CDとデプロイ戦略

**追加すべき質問**:

> **Q: ブルーグリーンデプロイメントとカナリアリリースの違いを説明してください**
>
> ブルーグリーン: 現行環境（Blue）と新環境（Green）を並行運用し、ロードバランサーの切り替えで一括移行。ロールバックが容易だが、同時に2倍のリソースが必要。
> カナリア: 新バージョンを少数のユーザー（例: 5%）に段階的に公開し、問題がなければ徐々に拡大。リスクを最小化できるが、ルーティングの制御が複雑。

#### Observability

**追加すべき質問**:

> **Q: オブザーバビリティの3本柱について説明してください**
>
> ログ: 離散的なイベントの記録。構造化ログ（JSON形式）が推奨
> メトリクス: 数値データの時系列集計（CPU使用率、レスポンスタイム等）
> トレース: リクエストがシステムを横断する際の処理経路を追跡。分散トレーシング（OpenTelemetry等）

#### 冪等性（Idempotency）

**追加すべき質問**:

> **Q: APIにおける冪等性（Idempotency）とは何ですか？なぜ重要ですか？**
>
> 冪等性とは、同じ操作を何度実行しても結果が変わらない性質のこと。HTTPメソッドでは、GET、PUT、DELETEは冪等であるべきだが、POSTは冪等ではない。冪等性が重要な理由は、ネットワーク障害やタイムアウト時にクライアントがリクエストをリトライしても安全であることを保証するため。実装方法としては、Idempotency Key（リクエストに一意のキーを付与し、サーバー側で重複を検出する）が一般的。StripeなどのAPIがこの方式を採用している。

### 5.4 DSA: 動的計画法（Dynamic Programming）

メガベンチャーのコーディング面接ではDP問題が頻出。基本概念の質問が来る可能性が高い。

**追加すべき質問**:

> **Q: 動的計画法（DP）とは何ですか？メモ化再帰との違いを説明してください**
>
> 動的計画法は、問題を部分問題に分割し、各部分問題の結果を保存して再利用することで効率的に解を求める手法。トップダウン方式（メモ化再帰）とボトムアップ方式（テーブルDP）がある。メモ化再帰は再帰呼び出しの結果をキャッシュする方法で、ボトムアップDPは小さな部分問題から順に解いていく方法。どちらも重複部分問題の再計算を避けることで、指数的な計算量を多項式時間に改善できる。代表的な問題: フィボナッチ数列、ナップサック問題、最長共通部分列（LCS）。

### 5.5 面接で問われやすい「比較」問題

メガベンチャーの面接では「AとBの違い」形式の問題が非常に多い。

**追加すべき質問**:

> **Q: モノリスとマイクロサービスの使い分けの判断基準は？**
>
> プロジェクト初期や小規模チームではモノリスが推奨される。マイクロサービスはチーム規模が大きくなり、独立したデプロイやスケーリングが必要になった段階で検討する。Martin Fowlerの「Monolith First」アプローチ。モノリスでドメイン境界が明確になってから段階的に分離するのが現実的。

> **Q: SQLデータベースとNoSQLデータベースの使い分けを説明してください**
>
> SQL（RDB）: 構造化データ、複雑なクエリやJOIN、ACID準拠が必要な場合（金融、EC等）。PostgreSQL、MySQL。
> NoSQL: スキーマの柔軟性、水平スケーリング、高スループットが求められる場合。ドキュメント（MongoDB）、KV（Redis, DynamoDB）、列指向（Cassandra）、グラフ（Neo4j）。
> 選定基準: データモデルの複雑さ、スケール要件、一貫性要件、チームの習熟度。

以下の回答は長すぎて面接で口頭説明する際に不利になる可能性がある。**30秒〜1分で説明できる長さ**に要約版も用意すべき。

## 7. JS Codingセクションの強化

現在5問しかなく、メガベンチャーのコーディング面接対策としては不足。以下を追加すべき。

**追加すべき問題**:

> **Q6. 次のコードの出力は何になりますか？**
> ```javascript
> const obj = { a: 1, b: 2, c: 3 };
> const { a, ...rest } = obj;
> console.log(rest);
> console.log(obj);
> ```
>
> **回答:** `{ b: 2, c: 3 }` と `{ a: 1, b: 2, c: 3 }`
> スプレッド構文/レスト構文の理解を問う問題。分割代入でrestにaを除いた残りのプロパティが浅いコピーで格納される。元のオブジェクトは変更されない。

> **Q7. 以下のdebounce関数を実装してください**
> ```javascript
> // debounce(fn, delay)を実装する
> // 使用例: const debouncedFn = debounce(() => console.log('called'), 300);
> ```
>
> **回答:**
> ```javascript
> function debounce(fn, delay) {
>   let timerId;
>   return function (...args) {
>     clearTimeout(timerId);
>     timerId = setTimeout(() => fn.apply(this, args), delay);
>   };
> }
> ```
> debounce/throttleの実装はメガベンチャーの面接で頻出。理論だけでなく実装できることが求められる。

> **Q8. 以下のPromise.allとPromise.allSettledの違いを説明し、それぞれの出力を答えてください**
> ```javascript
> const p1 = Promise.resolve(1);
> const p2 = Promise.reject('error');
> const p3 = Promise.resolve(3);
>
> // パターン1
> Promise.all([p1, p2, p3]).then(console.log).catch(console.error);
>
> // パターン2
> Promise.allSettled([p1, p2, p3]).then(console.log);
> ```
>
> **回答:**
> パターン1: `error`（1つでもrejectされると即座にcatchに入る）
> パターン2: `[{status: "fulfilled", value: 1}, {status: "rejected", reason: "error"}, {status: "fulfilled", value: 3}]`（全てのPromiseが完了するまで待ち、各結果をオブジェクトで返す）
> Promise.all / Promise.allSettled / Promise.race / Promise.anyの違いはメガベンチャーの面接で頻出。

> **Q9. 次のコードの出力は何になりますか？thisの挙動を説明してください**
> ```javascript
> const obj = {
>   name: 'Alice',
>   greet: function() { console.log(this.name); },
>   greetArrow: () => { console.log(this.name); }
> };
> obj.greet();
> obj.greetArrow();
> const greet = obj.greet;
> greet();
> ```
>
> **回答:** `Alice`, `undefined`, `undefined`
> - `obj.greet()`: メソッド呼び出しなのでthisはobjを指し、`Alice`を出力
> - `obj.greetArrow()`: アロー関数はレキシカルスコープのthisを参照。定義時のスコープ（グローバル/module）のthisを参照するため`undefined`
> - `greet()`: 関数が変数に代入されて呼び出されると、thisバインディングが失われる。Strictモードではthisは`undefined`、非Strictモードではグローバルオブジェクト（nameプロパティは通常undefined）
> thisの挙動はJS面接の最頻出トピックの一つ。

## 9. 学習戦略の提案

### 9.1 優先順位付けの推奨

面接までの時間が限られている場合、以下の順序で対策することを推奨:

1. **最優先**: 技術的な不正確箇所の修正（4章） - 面接で間違いを指摘されるのが最もリスクが高い
2. **高優先**: 認証・認可、システムデザインの準備（5.1章 + 5.3章）- メガベンチャーで必ず聞かれる
3. **中優先**: 回答が浅い問題の補強（3章）- 深掘り対応力の向上
4. **低優先**: フォーマット改善、追加トピック（6章 + 残り）- 網羅性の向上

### 9.2 模擬面接の推奨

問題集の暗記だけでなく、以下の練習を推奨:
- 各回答を**30秒〜1分で口頭で説明**する練習（長すぎる回答は面接で嫌われる）
- **ホワイトボードに図を描きながら**説明する練習（特にネットワーク、分散システム、システムデザイン）
- 回答後の**フォローアップ質問に即座に対応**する練習
