# 初代ポケモン セレクトバグの原理

## 参考元

- [セレクトバグ(ポケモン) - アニヲタWiki](https://w.atwiki.jp/aniwotawiki/pages/53234.html)
- [pokered 逆アセンブリ](https://github.com/pret/pokered) - ソースコードレベルでの検証

## 概要

初代ポケモン（赤・緑・青）に存在する有名なバグ技。
「道具の○番目でセレクトボタンを押した後、Bボタン2連打でキャンセルしてメニューコマンドを閉じる」という操作で発生する。

このバグを利用すると以下のようなことが可能になる：

- ポケモンのレベルを一気に100にする
- 本来覚えられない技を覚えさせる
- 希少アイテムを大量増殖させる
- 任意のポケモン（ミュウ含む）を生成する
- IDや個体値の変更

## セレクトバグの原理

### 1. セレクトボタンの待機状態が残るバグ

道具リストでセレクトボタンを1度押すと、「道具入れ替え」の待機状態に入る。
この時、RAM上の `wMenuItemToSwap`（アドレス CC35）に選択したアイテムのインデックスが格納される。

通常ならBボタンでキャンセルすれば待機状態も解除されるはずだが、初代ポケモン（日本語版 赤・緑・青）では**プログラムミスにより、CC35の値がリセットされないままリストを閉じてしまう**。

### 2. 待機状態が戦闘中の技リストに引き継がれる

メニューを閉じた後、戦闘画面に入って「たたかう」を選択すると、CC35に残った「○番目を入れ替える」という待機状態を保ったまま技のリストが開く。

### 3. 技リストの範囲外アクセス

初代ポケモンのようなゲームボーイ用ソフトはプログラムが非常に原始的で、メモリ上に「ここからここまでが技のデータ」というシステム的な区分けがない。開発者が「○番～○番までを技のデータとして使う」と決めているにすぎない。

そのため「7番目の技」を指定してもエラーにならず、**技データの直後に格納されている別のデータ**を読みに行ってしまう。

### 4. 技術的メカニズム（pokered逆アセンブリより）

戦闘中の技入れ替え処理 `SwapMovesInMenu` は以下の2つのデータ構造に対して同時にスワップを行う：

- **battle_struct**（`wBattleMonMoves` 起点）: 戦闘中の一時データ
- **party_struct**（`wPartyMon1Moves` 起点）: パーティの永続データ

この2つの構造体はレイアウトが異なるため、技スロット4を超えた範囲では別々のデータが破壊される。
経験値の操作に関わるのは **party_struct側のスワップ** である。

## パーティデータ構造（party_struct）の技スロット周辺メモリ配置

pokeredの逆アセンブリから確認したメモリレイアウト（全44バイト）：

| オフセット | スロット | 実際のデータ | サイズ |
|-----------|---------|------------|--------|
| 0x08 | 1番目 | 技1 | 1 byte |
| 0x09 | 2番目 | 技2 | 1 byte |
| 0x0A | 3番目 | 技3 | 1 byte |
| 0x0B | 4番目 | 技4 | 1 byte |
| 0x0C | **5番目** | **トレーナーID 上位バイト** | 1 byte |
| 0x0D | **6番目** | **トレーナーID 下位バイト** | 1 byte |
| 0x0E | **7番目** | **経験値 上位バイト** | 1 byte |
| 0x0F | **8番目** | **経験値 中位バイト** | 1 byte |
| 0x10 | **9番目** | **経験値 下位バイト** | 1 byte |
| 0x11~ | 10番目~ | 努力値(HPExp等) | 2 bytes~ |

経験値は **3バイト（24ビット）のビッグエンディアン整数** として格納されている。
最大値は 0xFFFFFF = 16,777,215。

## 7番目バグ（レベル100バグ）

最も有名なセレクトバグの応用。

### 手順

1. メニューから「どうぐ」を開き、上から7番目にカーソルを合わせてセレクトボタンを押す
2. Bボタンを2回押してメニューを閉じる
3. 草むらで野生ポケモンとエンカウントし、「たたかう」で適当な技を選択する
4. 選択した技の表示がバグればOK（バグった技は使わないこと）
5. 野生ポケモンを倒すと、経験値取得時にレベルが一気に100まで上がる

### なぜレベル100になるのか

技リストの7番目は、メモリ上では**経験値の上位1バイト**（オフセット 0x0E）に対応する。

技データとのスワップにより、この上位バイトに技IDの値（通常0x01以上）が書き込まれる。
経験値は3バイトのビッグエンディアンなので、上位バイトが変わると値が大幅に増加する。

例：上位バイトが 0x01 になった場合
- 経験値 = 0x01???? = 少なくとも65,536以上
- 多くのポケモンのレベル100到達経験値（約100万）を超える値になりカンスト

結果としてレベルが上限の100まで上がる。

### 注意点

- バグった技を使うとフリーズする可能性があるため、選ぶ技は攻撃技以外にすること
- 技を1つしか覚えていないポケモンでは使えない（必ず2つ以上技を覚えさせておく）
- この方法で上げたポケモンは努力値が入っていないため、通常育成した個体より弱い
- レベルアップで習得するはずの技を覚えられない
- 三段階進化の最終進化がレベルアップ条件の場合、進化できない

## 9番目バグ（技教えバグ）

好きな技を覚えさせるバグ技。

### 原理

技リストの9番目は**経験値の下位1バイト**（オフセット 0x10）に対応する。
技にはそれぞれ1バイトの技ID（1=はたく、2=からてチョップ 等）が割り当てられている。

経験値の下位1バイト = 経験値を256で割った余り（Exp mod 256）がそのまま技IDとして解釈される。
この値が目的の技IDと一致するように経験値を調整してからセレクトBBを行うことで、任意の技を覚えさせられる。

### 注意点

- 経験値の調整には育て屋が便利（1歩で経験値1獲得）
- 技IDの範囲は1～165（初代の技は165種類）。余りが166～255になると存在しない技データを呼び出し不具合が発生する
- 戦闘中は「最大HPを256で割った余りの数値に対応した技」を覚えるため、最大HPにも注意が必要

## 14番目バグ（道具増殖バグ）

道具の個数を増やせるバグ技。7番目・9番目バグより**危険度が高い**。

### 概要

道具リストの14番目でセレクトBBした後、戦闘中にバグ要員ポケモンを選択して道具データを操作する。
**一度バグを発生させた後、もう1度同じ手順を踏んで元の状態に戻す必要がある**（怠るとまともにプレイできなくなる）。

増殖数はバグ要員のニックネームの文字コードに対応しており、伸ばし棒「ー」（内部数値227）で最大227個まで増やせる。

## バグショップ

14番目バグでバグった状態のままフレンドリィショップに行くと、マスターボールやふしぎなアメなどが並ぶ異常な品揃えになる。

## ピカチュウバージョンでの修正

ピカチュウバージョン（および海外版 Red/Blue/Yellow）では、Bボタンキャンセル時にCC35を0にリセットする修正が入り、セレクトバグは使用不可になった。
日本語版では赤・緑・青の3バージョンでのみバグが存在する。

なお、技入れ替え処理 `SwapMovesInMenu` 自体はピカチュウバージョンにも存在しており、戦闘中の技順入れ替え機能は正常に動作する。修正されたのは「メニュー間でCC35が持ち越される」というバグの根本原因のみ。

## 補足

- バーチャルコンソール版でも使用可能
- 現在は原理が完全に解明され、ゲーム内でバイナリエディタを作成したり、プログラミングで新たなゲームやイベントを自作することまで可能になっている
- セレクトバグで変化させたポケモンを育て屋やポケモンスタジアムで使うと元に戻る場合がある（見た目データと中身データの不一致による）
- battle_struct と party_struct は技スロット4以降のレイアウトが異なる。battle_struct側では技5番目以降はDVs（個体値）、Level、MaxHP等に対応するため、セレクトバグは両方の構造体に対して同時にデータ破壊を引き起こす
